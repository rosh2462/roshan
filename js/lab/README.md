# HiWi lab — real-time 3D (chapter 03, scene B)

A miniature university computer lab that is built piece by piece as you scroll,
then switched from a modelling viewport into a lit scene, then walked into.
The whole scene is a pure function of one number, `HiWiLabState.progress`
(0 → 1), which `js/story.js` writes from the scrubbed GSAP timeline — so
scrolling back takes the lab apart again.

The room layout, construction schedule, materials, screens, lighting and camera
tracks retain the original `e36d20e` university-lab design. The existing reduced
head movement on phones is retained. No textures, geometry, shadow-map sizes,
pixel-density caps or bloom settings are reduced for scroll performance.

Rendering uses the chapter's visible-state/scroll clock and wakes directly on
`sceneprogress`. Only a changed pose updates the room's world matrices; its
full-resolution shadow map is rebuilt during construction and monitor lifts,
and reused while the room and casters stand still. Resizes, context restoration,
light/target transforms and shadow-camera projection changes invalidate the map.
Dust keeps animating normally.

Shader preparation (`prepare()` in `lab.js`) compiles every program before the
first frame needs it: the room against an offscreen key target (three.js keys a
program by what it draws into, and the room renders into the post target, not
the screen), the shadow pass's depth variants through stand-in meshes, and the
post passes; then each program's first use and the texture uploads. Each step
waits for a pause in the scrolling (`window.SceneIdle`, js/face/boot.js), or
runs at once if the visitor arrives first. The room itself is built in pieces
during the same pauses. `HiWiLabState.prepareLog` records the steps.
`renderer.info.programs.length` should not grow while the lab is scrolled.

Once the monitor is selected it powers on (a CRT-style line opening into the
picture) into a NeuroMaze preview: the real gameplay capture with REC, the
title, a pulsing play button and an "In Creative works" caption (`preview.js`).
Mouse/pen hover lifts the button; a short click/tap on the monitor, or its
"NeuroMaze · Up next" label (also a keyboard button), flashes the screen and
glides the page on to chapter 04's shelf, where NeuroMaze waits in front and
glows once (`js/works.js`, `WorksPlayer.showShelf()`). The monitor is a
signpost, not a second way in: the games open only from the shelf, and
scrolling past the lab is never held. Without works.js the label simply
scrolls to the chapter.

Pointer listeners are passive: movement over 8 CSS pixels, pointer
cancellation, a press over 500 ms, or changed lab scroll progress cancels a
tap. Native page scrolling is preserved.

The capture is embedded as a data URI (`neuromaze-screen.js`, generated by
`python js/lab/build-neuromaze-screen.py` from `assets/neuromaze-capture.webp`)
because WebGL cannot read local image files when the site is opened from disk.

`ResizeObserver` and `IntersectionObserver` have fallbacks. A lost WebGL context
sleeps the renderer and restores its pose/shaders/shadows when available again.
Without WebGL 2 the original caption-based fallback still works; without the
scroll driver the finished lab remains still and its label can still be used.

## The story it tells (L = lab progress, 0 → 1)

| Stage | L | What you see |
| --- | --- | --- |
| **1 · Blender** | 0 → 0.5 | The room is modelled and assembled: slab, tiles, walls, then furniture drops in. Each piece appears as an amber blocking cage, moves into place and dissolves into its solid form. The ground grid and flat, cool "viewport" lighting stay on; the workstation screen shows Blender. |
| **2 · Unity** | 0.53 → 0.67 | Same room, same objects — only the lighting changes: the grid recedes, a warm key light and real shadows come up, the desk lamps switch on, the colour grade goes from flat to rich, and the workstation screen cross-fades from Blender to the Unity editor. |
| **3 · XR** | 0.72 → 1 | The camera leaves the isometric miniature and walks into the lab, widening its lens as it goes so the model becomes a place. It settles on the central workstation; the viewer's ray reaches the monitor (hover: a fine outline), then picks it (select: the outline firms up, the monitor lifts a hair and powers on into the NeuroMaze preview, the rest of the frame falls back, and a label invites a click/tap). |

The captions in `js/story.js` (`buildConsole`) are timed against these windows;
keep the two in step if you retime a stage. The Blender and Unity marks beside
the captions are in `index.html`; the same glyphs (`logos.js`) are painted onto
the monitor screens.

## What runs in the browser

`index.html` loads only `boot.js` (a tiny classic script). When the visitor gets
within a couple of screens of the chapter it injects **`lab.bundle.js`**: the
modules in this folder plus three.js r170, bundled into one classic script. A
classic script (not ES modules) is deliberate: modules cannot be loaded from
`file://`, and the site should work opened straight from disk.

`lab.bundle.js` is a **build artifact — don't edit it**. It now includes the
portrait renderer through `js/scene-3d.js`, sharing one copy of Three.js and one
cached download between the portrait and the lab. Edit the sources, then rebuild.

## Rebuilding after editing the sources

Needs Node. From the site root:

```bash
npm install --no-save three@0.170.0 esbuild
node js/build-scenes.mjs
```

Then bump the `?v=` on both `js/face/boot.js` and `js/lab/boot.js` in
`index.html`, and use the same new `lab.bundle.js` version inside both boot
scripts, so browsers fetch the new files.

## Where things are

| File | Job |
| --- | --- |
| `config.js` | palette, room and furniture layout, the **build schedule** (`SCHEDULE`) and the **camera keyframes** (`CAMERA`) — the knobs for timing and framing |
| `timeline.js` | easing and the smooth camera-track curve |
| `kit.js` | `part()`: the amber-cage → solid "modelling" effect every big piece shares; `solid()` for small props |
| `shapes.js` | geometry builders: chairs, monitors, keyboards, headset, plants… (each merged into one mesh) |
| `materials.js` | the material set (matte = cheap Lambert, glossy = PBR + reflections), reflection map, canvas-texture helpers |
| `screens.js`, `logos.js` | everything painted onto a canvas: Blender/Unity/code screens, whiteboard, clock, locker fronts… |
| `preview.js`, `neuromaze-screen.js` | the NeuroMaze preview on the selected monitor (painted layers + a small shader) and its embedded capture |
| `components/` | `floor`, `walls`, `desks`, `storage`, `island` (back table), `workstation` (the hero desk), `props`, `interaction` (ray, outline, label), `grid`, `atmosphere` |
| `camera-rig.js`, `lighting.js` | the camera path and lens; the two lightings (viewport → Unity) |
| `post.js` | light bloom, the colour grade with the output tone mapping folded in, FXAA — built to be cheap on integrated GPUs |
| `lab.js` | renderer, run loop (draws only while on screen), quality tiers, shader preparation |
