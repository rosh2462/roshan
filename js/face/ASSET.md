# Portrait particle targets and presentation

The transition uses **artist-defined particle targets from a single photograph**. The geometry supplies positions for particles only; its shallow depth is an approximation, not a 3D scan, a trained reconstruction, or an anatomical head model. The completed reveal uses the original sharp native DOM photograph, clipped and framed to match the target silhouette. It does not promise a rotatable model or unseen sides.

`assets/face/portrait-depth.bin.gz` contains quantized target geometry and sampled vertex colors. HTTP previews lazily fetch the 62 KB gzip file and decompress it with `DecompressionStream`; older engines request the 73 KB raw `.bin` fallback. Direct `file://` previews instead lazily inject the generated classic `portrait-data.js` script, which supplies the same raw binary as base64 through `window.PortraitEmbeddedData`. This approximately 97 KB script needs neither fetch permissions nor a decompression library. No asset is requested when merely importing the loader. The unchanged 56 KB `assets/roshan-reveal-after.webp` supplies the completed DOM portrait.

Rebuild with `node js/face/build-asset.mjs --python <Python executable with Pillow>`. Pillow reads the source RGB pixels only; it does not alter the photograph. A detailed source-space contour follows the hair, ears, jaw, neck, and shoulders without admitting the original backdrop into clipped wedges. The same outline generates the particle geometry, SVG alpha mask, and fallback CSS clip. Its geometry ends at source Y=700 to frame a head and upper-chest bust; the photograph and its UV space remain unchanged. Exact contour intersections and extra ear/neck rows form the silhouette; a coarse interior grid connects them with monotone triangle strips. Particle XY coordinates and header bounds use the fixed declared crop, so small mask insets never move or resize the portrait. Its JSON sidecar records the source crop, counts, dimensions, and compressed size.

The binary starts with a 40-byte little-endian header: ASCII `RDP1`, vertex count, index count, minimum XYZ bounds, maximum XYZ bounds, and layout version `1`. Data follows as position XYZ (`Uint16` normalized within bounds), UV (`Uint16` normalized), color RGB (`Uint8`), and triangle indices (`Uint16`). Coordinates use Y up and Z toward the viewer; the bounds midpoint is the origin and portrait height is 2 units. UVs address the complete original WebP, with V increasing upward. Triangles face +Z.

The loader exports `loadPortraitAsset({ signal, baseUrl } = {})`, `parsePortraitAsset(arrayBuffer, { textureUrl } = {})`, and `portraitPresentation`. Its default `baseUrl` is `assets/face/` resolved against `document.baseURI`, so it also works in an IIFE bundle and under a site subpath. The renderer receives `{ positions, colors, uvs, indices, textureUrl, bounds, presentation, kind }`, with float arrays for positions/colors/UVs and Uint16 indices. `kind` explicitly identifies the target representation as `photo-depth-approximation`. File-preview script loads are shared and can be cancelled per caller without disrupting another caller; a failed script load can be retried. After decoding, the global base64 payload is released and only the reusable binary promise is retained.

`portraitPresentation` provides the original raster dimensions, fixed source crop rectangle, source-space outline, normalized outline, CSS `clipPath`, full-source SVG `maskImage`, and `imageCss` percentages. The crop rectangle is `{ left: 150, top: 37, width: 662.9574468085107, height: 663 }`. For a bust height H, scale the original image by H/663, set the bust width to H×`presentation.aspect`, and offset the original image by −150 and −37 at that scale. Alternatively, apply the supplied image percentages inside the bust container, with `max-width: none` and no extra object-fit crop. A flat or orthographic final particle projection matches this DOM crop; perspective distortion would require an additional alignment adjustment. Consumers must use the declared `data.bounds` instead of recomputing framing from the tighter outline's extrema.

The generator also writes `css/portrait-mask.css`. Its small SVG mask is embedded as a CSS data URL to work under both HTTP and direct file previews without an external SVG request. Short 1.25-source-pixel quadratic corner curves remove hard polygon points without blurring the photograph; the same curves are sampled to subpixel precision for the particle outline. The enhanced photo image uses `mask-size: 100% 100%`; its existing wrapper supplies the lower fade. The unenhanced and reduced-motion source image uses `mask-size: cover`, with mask positions matching each responsive `object-position` rule. The full-source mask retains the body's natural lower silhouette, so unenhanced layouts do not acquire an abrupt new chest crop. No image filter, blur, glow, or photo reencoding is used.

Asset version 6 tightens only the local lower-jaw and neck edges against the source pixels, including the small transition below each earlobe. The previous matte admitted a 4–7-source-pixel strip of the flat brown backdrop along the right jaw/neck. Hair and upper-ear contours, full-resolution source bytes, declared frame, and lower fade are retained. Four-times-source-scale browser comparisons verify the repaired edge without reencoding or editing the photograph.
